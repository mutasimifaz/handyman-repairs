HANDYMAN - PAYMENT + CATALOGUE FIX

WHAT THIS PATCH CHANGES
1. Homepage now loads up to 6 products (instead of 3).
2. Product cards use a regular responsive grid and no longer make the first card span two columns.
3. Product cards keep consistent alignment and show product images with contain sizing.
4. IMPORTANT PAYMENT FIX:
   - After Stripe sends the customer back to /payment/success, the page now asks the Worker to verify the Checkout Session directly with Stripe.
   - The Worker checks the real Stripe session, verifies that it is paid and belongs to the signed-in customer, then updates the Firestore order and product stock together.
   - This gives the customer-return flow a direct confirmation path instead of relying only on a webhook arriving first.
   - The existing Stripe webhook is retained. Both paths use the same idempotent stock update, so a webhook and the return-page confirmation cannot decrement the same order twice.
   - Product stock is read from available_quantity (the field used by the Admin page), with stock as a fallback.
   - If stock is no longer sufficient after payment, the order is marked stock_conflict and stock is not made negative.

- Keep the existing Worker secrets. Do not delete or recreate them.
- In the Cloudflare Worker settings, make sure ALLOWED_ORIGIN is the exact public website origin (for example, https://your-site.example), not http://localhost:5173. Do not change it to a guessed domain.
- Keep FIREBASE_PROJECT_ID set to handyman-repairs.
- Keep the existing Stripe and Firebase secrets already configured in Cloudflare.
